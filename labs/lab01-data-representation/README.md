# Lab 1: Представлення даних у пам'яті

## 1. Розміри типів даних

Результати програми `types.c`:

- char: 1 byte (8 bits)
- short: 2 bytes (16 bits)
- int: 4 bytes (32 bits)
- long: 8 bytes (64 bits)
- long long: 8 bytes (64 bits)
- float: 4 bytes (32 bits)
- double: 8 bytes (64 bits)
- void *: 8 bytes (64 bits)

Типи займають різну кількість пам'яті. Розмір `void *` дорівнює 8 bytes, тому середовище 64-бітне.

## 2. Decimal, Hexadecimal, Binary

Програма `representations.c` виводить decimal і hex, binary визначено вручну:

- 10 = 0x0A = 00001010
- 65 = 0x41 = 01000001
- 127 = 0x7F = 01111111
- 255 = 0xFF = 11111111
- 256 = 0x0100 = 00000001 00000000
- 1024 = 0x0400 = 00000100 00000000

65, 0x41 і 01000001 — це одне число в десятковій, шістнадцятковій та двійковій системах.

## 3. Binary

Програма `binary.c` виводить числа у двійковому форматі. Наприклад, 65 = 01000001. Функція починає з біта 7, щоб виводити біти від старшого до молодшого (як ми читаємо число зліва направо).

Перевірені значення: 0, 1, 10, 65, 127, 128, 255.

## 4. Characters

Програма `characters.c` показала числові коди символів:

- A = 65 = 0x41
- B = 66 = 0x42
- a = 97 = 0x61
- 0 = 48 = 0x30
- 9 = 57 = 0x39

У пам'яті символ зберігається як числовий код.

## 5. Signed та Unsigned

У програмі `signed_unsigned.c` отримано:

- int8_t: -1, Hex: 0xFF
- uint8_t: 255, Hex: 0xFF

Однакові біти (11111111) можуть мати різні значення залежно від типу даних.

## 6. Overflow

Прогноз: 255 + 1 = 0.

У програмі `overflow.c` отримано:

- 254 + 1 = 255
- 255 + 1 = 0
- 255 + 2 = 1

Прогноз підтвердився. Тип uint8_t має 8 бітів і зберігає значення від 0 до 255. Результат 256 потребує 9 бітів, дев'ятий біт відкидається, тому після 255 значення переходить до 0. Це стосується саме unsigned-типу.

## 7. Memory та Endianness

Прогноз: для числа 0x12345678 у пам'яті буде 12, 34, 56, 78 (варіант A).

У програмі `memory.c` досліджено число 0x12345678. Результат у пам'яті: 78, 56, 34, 12. Прогноз виявився хибним, правильним був варіант B.

Програма `endian.c` вивела адреси байтів:

- 0x7ffc5517ed08: 0x78
- 0x7ffc5517ed09: 0x56
- 0x7ffc5517ed0a: 0x34
- 0x7ffc5517ed0b: 0x12

Адреси зростають, а молодший байт розташований за найменшою адресою. Це означає, що система використовує Little-endian. Саме число не змінилось, змінився лише порядок його байтів у пам'яті.

## 8. Inspect

Програма `inspect.c` для числа 65 показала:

- Decimal: 65
- Hexadecimal: 0x41
- Binary: 01000001
- Character: A

Для числа 10 символ не виводиться (він недрукований), а для 300 програма виводить повідомлення про помилку.

## 9. Контрольні питання

- Біт — це 0 або 1, байт — 8 бітів.
- За допомогою n бітів можна представити 2^n значень.
- Діапазон uint8_t: від 0 до 255.
- Діапазон int8_t: від -128 до 127.
- Hexadecimal зручний, бо одна цифра відповідає 4 бітам.
- 11111111 як uint8_t — це 255, а як int8_t — це -1.
- Після 255 значення uint8_t переходить до 0.
- Символ A має числовий код 65.
- Endianness — це порядок байтів у пам'яті.
- Досліджувана система використовує Little-endian.
- sizeof(int) повертає розмір int у байтах. У моєму середовищі це 4 байти.
- Однакові біти можуть мати різні значення залежно від типу та контексту.
