# Lab 2: Від C до Assembly та machine code

Середовище: GitHub Codespaces, Ubuntu, GCC 13.3, GNU Binutils (objdump),
архітектура x86-64. Усі результати відтворюються командами `gcc` та `objdump`
з файлів `.c` у цьому каталозі.

## 1. Результати експериментів

### arithmetic.c

Прогноз до перегляду Assembly: CPU має провести розрахунок a + b, тобто взяти
значення a і b, додати їх і зберегти результат.

Програма виводить `Result: 12`. Assembly отримано командою
`gcc -Wall -Wextra -O0 -S arithmetic.c -o arithmetic.s`
(за замовчуванням AT&T syntax) та з параметром `-masm=intel`.

- Одному рядку C не відповідає одна інструкція: `int result = a + b;` дає
  декілька (завантаження a та b у регістри, `add`, збереження результату).
- Змінних a, b, result в Assembly немає: вони стали ячейками стеку
  (`-12(%rbp)`, `-8(%rbp)`, `-4(%rbp)`).
- Тіло `main` займає 19 інструкцій (від `endbr64` до `ret`).
- Операція додавання є: `addl %edx, %eax` (AT&T) або `add eax, edx` (Intel).

### operations.c

Програма виводить `30`. Функція `calculate(a, b)` отримує аргументи в регістрах
`edi` (a) і `esi` (b), зберігає їх у стеку, виконує операцію в `eax` і повертає
результат у `eax`.

### condition.c

Програма виводить `20`. У `max_value` знайдено `cmp`, умовний перехід `jle` та
дві гілки (return a / return b).

### loop.c

Програма виводить `15`. У `sum_to` знайдено `cmp`, умовний перехід назад `jle`,
тіло циклу та збільшення лічильника.

### Виклик функції

У `main` перед викликом `mov esi, 20` і `mov edi, 10` кладуть аргументи в
регістри, далі `call calculate`. Функція завершується `pop rbp` і `ret`, а
результат лежить у регістрі `eax` (одразу після `call` він зберігається в
змінну `value`).

### objdump

Командою `objdump -d -M intel operations` отримано дизасемблювання
`calculate`: адреса, байти machine code, Assembly. Наприклад:

- `115d: 01 d0` це `add eax,edx`
- `1151: 89 7d ec` це `mov DWORD PTR [rbp-0x14],edi`
- `1166: c3` це `ret`

### optimize.c

Прогноз: варіант A (компілятор створить `load 10`, `load 20`, `add`, `return`).
Результат: прогноз хибний. Навіть на `-O0` для `return 10 + 20;` компілятор
створив `mov eax, 30` (обчислення константного виразу під час компіляції). На
`-O2` зникли `push rbp` / `mov rbp, rsp` / `pop rbp`, а `main` вбудувала
`answer` і стала `mov eax, 30` + `ret`.

## 2. Арифметичні операції C → Assembly

Змінювалась лише одна операція в `operations.c` (команда
`gcc -O0 -S -masm=intel operations.c`):

| C | Основна Assembly-інструкція |
|---|---|
| `a + b` | `add eax, edx` |
| `a - b` | `sub eax, DWORD PTR -24[rbp]` |
| `a * b` | `imul eax, DWORD PTR -24[rbp]` |

Змінилась лише одна інструкція. Решта (збереження аргументів `edi` і `esi`,
збереження результату, `ret`) лишилась тією самою.

## 3. Реалізація if

`max_value` у `condition.c` (Intel syntax):

```
mov     eax, DWORD PTR -4[rbp]      ; a
cmp     eax, DWORD PTR -8[rbp]      ; порівняти a з b
jle     .L2                         ; якщо a <= b, перейти до else
mov     eax, DWORD PTR -4[rbp]      ; return a
jmp     .L3
.L2:
mov     eax, DWORD PTR -8[rbp]      ; else: return b
.L3:
pop     rbp
ret
```

Відповідність:

- `if (a > b)` це `cmp` + `jle .L2`
- `return a` це `mov eax, a` + `jmp .L3`
- `else` це мітка `.L2:`
- `return b` це `mov eax, b` після `.L2:`

Машинної інструкції `IF` немає. `cmp` порівнює значення й виставляє прапорці
процесора, а умовний перехід за прапорцями або змінює Instruction Pointer
(стрибок на гілку else), або не змінює (виконується наступна інструкція).
Компілятор записав умову навиворіт: `jle` стрибає до else, коли `a <= b`.

## 4. Реалізація циклу

`sum_to` у `loop.c`:

```
mov     DWORD PTR -8[rbp], 0        ; sum = 0
mov     DWORD PTR -4[rbp], 1        ; i = 1
jmp     .L2                         ; спочатку перевірити умову
.L3:
mov     eax, DWORD PTR -4[rbp]
add     DWORD PTR -8[rbp], eax      ; sum += i
add     DWORD PTR -4[rbp], 1        ; i++
.L2:
mov     eax, DWORD PTR -4[rbp]
cmp     eax, DWORD PTR -20[rbp]     ; i <= n ?
jle     .L3                         ; так: повернутись до тіла
mov     eax, DWORD PTR -8[rbp]      ; return sum
```

- Порівняння виконує `cmp`, перехід `jle` (умовний назад) і `jmp` (безумовний
  на перевірку умови).
- Поняття `for` в Assembly немає: є ініціалізація, порівняння, умовний
  перехід, тіло, інкремент і перехід назад.
- CPU вирішує повторити цикл за прапорцями після `cmp`: `jle` повертається до
  `.L3`, поки `i <= n`, інакше виконання йде далі.

## 5. Machine code bytes → Assembly

Із виконуваного файлу `analyze` (`objdump -d -M intel analyze`):

| C | Address | Machine-code bytes | Assembly |
|---|---|---|---|
| `result = a - b;` | 0x1169 | `2b 45 e8` | `sub eax, DWORD PTR [rbp-0x18]` |
| `i++` | 0x118b | `83 45 fc 01` | `add DWORD PTR [rbp-0x4], 0x1` |
| `return` | 0x1199 | `c3` | `ret` |

Додатково з `main`: виклик `analyze(10, 4)` це `11ac: e8 98 ff ff ff` =
`call 1149 <analyze>`. Інструкції мають різну довжину (від 1 до 7 байтів).
Умова `i < 3` компілятор записав як `cmp DWORD PTR [rbp-0x4], 0x2` + `jle`
(`83 7d fc 02`, `7e ee`), а `i * 2` як `add eax, eax` (`01 c0`).

Програма `analyze.c` містить окрему функцію з двома параметрами, арифметику
(`a - b`, `b - a`, `i * 2`), `if/else`, цикл `for` і повернення результату.
Вона виводить `Result: 12`.

## 6. Порівняння -O0 та -O2

`operations.c`:

- Без оптимізації (`-O0`) файл `operations_O0.s` має 78 рядків, з оптимізацією
  (`-O2`) `operations_O2.s` має 58 рядків.
- На `-O2` у `main` немає `call calculate`: результат `10 + 20` обчислено під
  час компіляції (`mov edx, 30`), змінні не лежать у стеку, а `printf`
  замінено на `__printf_chk`.

`optimize.c`: на `-O0` і `-O2` результат `answer()` однаково `mov eax, 30`, на
`-O2` ще й зникає кадр стеку, а `main` вбудовує `answer`. Висновок: C-код не
має єдиного незмінного Assembly-представлення.

## 7. Контрольні питання

1. ISA (Instruction Set Architecture) визначає, які інструкції, регістри,
   способи адресації та правила роботи з пам'яттю та потоком виконання бачить
   програма. Це інтерфейс між програмним і апаратним забезпеченням (у нас
   x86-64).
2. CPU виконує лише машинні інструкції своєї ISA і не знає змінних, типів та
   операторів мови C, тому компілятор має перетворити C на машинний код.
3. Assembly це текстове представлення інструкцій (`add eax, edx`), а machine
   code це байти (`01 d0`), які виконує CPU. Асемблер перетворює перше на друге.
4. `-S` зупиняє компіляцію після генерації Assembly.
5. `-O0` вимикає оптимізацію, щоб Assembly був близький до C і його було легко
   зіставляти з рядками програми.
6. Operand це дані, з якими працює інструкція: число, регістр або комірка
   пам'яті.
7. `mov` копіює значення (число в регістр, регістр у регістр, пам'ять у
   регістр чи навпаки).
8. `cmp` порівнює два значення і виставляє прапорці, за якими наступний
   умовний перехід приймає рішення.
9. `if` це `cmp` плюс умовний перехід (`jle` та ін.) на гілку else, а в кінці
   першої гілки `jmp` пропускає другу.
10. Цикл це ініціалізація, перевірка умови (`cmp`), умовний перехід назад до
    тіла, тіло, інкремент.
11. `call` зберігає адресу повернення в стеку і передає керування функції.
12. `ret` бере адресу повернення зі стеку і повертає виконання туди, звідки
    викликали функцію.
13. Один рядок C може потребувати кількох інструкцій (завантажити, обчислити,
    зберегти), а компілятор до того ж може об'єднувати, прибирати або змінювати
    інструкції.
14. `objdump -d` показує дизасемблювання machine code виконуваного файлу:
    адресу, байти та Assembly кожної інструкції.
15. `-O2` використовує регістри замість пам'яті, вбудовує функції, обчислює
    константи під час компіляції та прибирає зайві операції, тому код суттєво
    відрізняється від `-O0`.
16. Так, якщо це не змінює спостережувану поведінку програми (правило as-if):
    наприклад, обчислення, результат якого не використовується, або константний
    вираз. У нашому експерименті виклик `calculate` у `main` зник, а `10 + 20`
    було замінено на `30`. Код із побічними ефектами (виведення, зміна
    змінних, що використовуються) видаляти не можна.

## 8. Висновок

Під час лабораторної роботи я простежив шлях від C до Assembly і machine code.
Я побачив, що змінні C перетворюються на регістри та ячейки стеку, `+`, `-`,
`*` на `add`, `sub`, `imul`, `if` на `cmp` та умовний перехід, цикл на перевірку
умови й перехід назад, а виклик функції на `call` та `ret` з результатом в
`eax`. Machine code це байти різної довжини, а `objdump` показує їх разом з
Assembly. Оптимізація змінює Assembly (навіть прибирає виклики та обчислює
значення заздалегідь), тому C-код не має єдиного Assembly-представлення.
